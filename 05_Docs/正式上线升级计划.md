# 正式上线升级计划

当前项目已经具备“替换适配器即可接入”的工程结构，默认配置仍可离线运行。正式上线前按下面顺序替换基础设施，不需要重写 Agent 编排核心。

## 已具备的可替换接口

- 事件总线：`InMemoryEventBus` / `KafkaEventBus`，通过 `AIOPS_EVENT_BUS` 切换。
- 拓扑：JSON / Neo4j，通过 `AIOPS_TOPOLOGY` 切换。
- 安全状态：内存 / Redis，通过 `AIOPS_SAFETY_BACKEND` 切换。
- 模型：离线 / DeepSeek / OpenAI 兼容接口，通过 `AIOPS_LLM` 切换。
- 修复执行：dry-run / allowlist，通过 `AIOPS_REPAIR_EXECUTOR` 切换。
- CMDB：本地 JSON / HTTP CMDB，通过 `AIOPS_CMDB` 切换。
- RAG：本地文档检索 / HTTP 向量库适配，通过 `AIOPS_RAG` 和 `AIOPS_VECTOR_DB_URL` 切换。
- 可观测性：本地 JSON 日志 / Loki / Jaeger，通过对应 URL 环境变量切换。

## 上线前必须完成

1. 当前已提供 PostgreSQL TaskStore 适配器；上线时设置 `AIOPS_STORAGE=postgres` 和 `AIOPS_DATABASE_URL`，再执行备份、迁移和连接池参数验收。
2. 提供 Kafka 集群地址、认证证书和内部监听地址，创建 `aiops.alerts`、`aiops.events`、`aiops.commands`、`aiops.audit` 及对应 DLQ。
3. 提供 Neo4j 集群、CMDB 地址和 Qdrant/其他向量数据库地址，导入真实服务拓扑、变更记录和历史故障文档。
4. 配置 DeepSeek 或企业模型密钥，并接入密钥管理服务，禁止把密钥写入 Compose 文件。
5. 将 allowlist 命令替换为企业变更平台 API，加入审批、回滚、超时和操作人审计。
6. 在 Kubernetes 或企业容器平台配置副本数、滚动发布、网络策略、TLS、资源限制和 Secret。
7. 接入 Prometheus/Grafana、Loki、Jaeger 告警，验证 P95 延迟、失败率、队列堆积和熔断次数。
8. 完成压测、故障演练、备份恢复、权限审计和灰度发布验收。

## 上线验收标准

- API `/health` 存活，`/ready` 仅在所有必需依赖可用时返回 200。
- Worker 注册 `aiops.handle_incident`，消息重试和 DLQ 可观察。
- 同一事件重复投递不会重复执行修复。
- L0 自动执行、L1 值班审批、L2 管理员审批路径均有审计记录。
- 执行后健康检查失败时自动回滚或转人工处理。
- 任意外部依赖不可用时，系统可降级且不会执行未审批变更。
