# 企业级多 Agent 智能运维系统运行手册

## 1. 环境

- Windows PowerShell 7
- Python 3.11 或更高版本
- 离线核心流程只需要 Python 标准库
- FastAPI、Kafka、Neo4j、Redis、Celery 按需安装对应依赖文件

以下命令默认在项目根目录 `Project024_EnterpriseAIOps` 执行。

`.env.example` 仅是配置参考，程序不会自动读取 `.env`；需要在当前 PowerShell 会话中设置环境变量。

## 2. 一键验证

```powershell
pwsh.exe -NoProfile -File .\02_Source\agent_tech_portfolio\verify.ps1
```

该脚本会运行当前全部自动化测试、Python 编译检查和 Git 差异检查。

## 3. 离线运行

```powershell
& ".\02_Source\agent_tech_portfolio\start_api.ps1"
```

另开 PowerShell 测试：

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health
Invoke-RestMethod http://127.0.0.1:8000/ready
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8000/api/v1/incidents `
  -ContentType "application/json" `
  -Body '{"service":"order-service","metric":"cpu","value":95,"baseline":[40,41,39,42,40]}'
```

`/health` 是进程存活检查。`/ready` 是依赖就绪检查：SQLite 执行 `SELECT 1`，Kafka 只读取元数据，Neo4j 只验证连通性。检查结果缓存 5 秒，必需依赖异常返回 HTTP 503。DeepSeek 和其他远程 LLM 仅检查客户端配置，不会因为健康检查产生模型调用费用。

## 4. DeepSeek（企业 API 默认优先）

```powershell
$env:AIOPS_LLM = "deepseek"
$env:AIOPS_DEEPSEEK_API_KEY = "你的密钥"
$env:AIOPS_DEEPSEEK_MODEL = "deepseek-chat"
$env:PYTHONPATH = (Resolve-Path .\02_Source\agent_tech_portfolio).Path
python -m api_server
```

也可以不设置 `AIOPS_LLM`：只要存在 `AIOPS_DEEPSEEK_API_KEY`，程序会自动选择 DeepSeek；没有密钥时自动回退到离线模式。

密钥只放在当前终端环境变量中，不要写入仓库、日志或提交记录。接口地址可通过 `AIOPS_DEEPSEEK_ENDPOINT` 覆盖。

## 5. API Key 认证与权限

仅本机离线演示时可保持默认关闭。共享或公网环境启动前，使用强随机密钥：

```powershell
$keyBytes = New-Object byte[] 32
[Security.Cryptography.RandomNumberGenerator]::Fill($keyBytes)
$apiKey = [Convert]::ToBase64String($keyBytes)
$env:AIOPS_AUTH_ENABLED = "true"
$env:AIOPS_API_KEYS = ConvertTo-Json @{$apiKey = "admin"} -Compress
& .\02_Source\agent_tech_portfolio\start_api.ps1
```

调用受保护接口：

```powershell
Invoke-RestMethod http://127.0.0.1:8000/api/v1/tasks -Headers @{"X-API-Key" = $apiKey}
```

角色从低到高为 `viewer` 、`operator`、`approver`、`admin`；高级角色继承低级权限。未携带或密钥错误返回 401，权限不足返回 403。启用认证但 `AIOPS_API_KEYS` 为空、不是 JSON 对象或密钥少于 16 位时，服务会拒绝启动。人工审批事件记录角色和 12 位 Key 指纹，用于追踪审批来源，但不保存原始密钥。

## 7. Redis 和 Celery

安装依赖并确保 Redis 在 `localhost:6379` 运行：

```powershell
python -m pip install -r .\02_Source\agent_tech_portfolio\requirements-production.txt
$env:AIOPS_CELERY_BROKER = "redis://localhost:6379/0"
& .\02_Source\agent_tech_portfolio\start_worker.ps1
```

另开 PowerShell 提交完整异步任务：

```powershell
$sourceDir = (Resolve-Path .\02_Source\agent_tech_portfolio).Path
$env:PYTHONPATH = $sourceDir
python -c "from celery_app import celery_app; r=celery_app.send_task('aiops.handle_incident', kwargs={'service':'order-service','metric':'cpu','value':95,'baseline':[40,41,39,42,40]}); print(r.get(timeout=30))"
```

Windows 本地 Worker 使用 `--pool=solo`。停止 Worker 在运行窗口按 `Ctrl+C`。

另开 PowerShell 检查 Worker 是否注册了本项目任务：

```powershell
& .\02_Source\agent_tech_portfolio\check_worker.ps1
```

脚本只在找到注册了 `aiops.handle_incident` 的 Worker 时返回退出码 0；只有其他项目 Worker 在线时仍返回 1。

多 API 实例共享限流和熔断状态：

```powershell
$env:AIOPS_SAFETY_BACKEND = "redis"
$env:AIOPS_SAFETY_REDIS_URL = "redis://localhost:6379/0"
$env:AIOPS_SAFETY_KEY_PREFIX = "project024:aiops:safety"
& .\02_Source\agent_tech_portfolio\start_api.ps1
```

该模式需要 `requirements-production.txt` 中的 Redis 客户端。Redis Lua 脚本保证多实例下的限流和熔断更新原子性，`/ready` 同时检查该安全状态后端。共享 Redis 时保留项目专属 Key 前缀，避免与其他项目冲突。

## 8. Kafka 和 Neo4j

需要时执行：

```powershell
docker compose -f .\02_Source\agent_tech_portfolio\docker-compose.production.yml up -d kafka neo4j
```

不使用时只停止容器，不删除数据卷：

```powershell
docker stop agent_tech_portfolio-kafka-1 agent_tech_portfolio-neo4j-1
```

完整 Compose 栈还提供 PostgreSQL 和 Qdrant：

```powershell
docker compose -f .\02_Source\agent_tech_portfolio\docker-compose.production.yml up -d postgres qdrant kafka
$env:AIOPS_STORAGE = "postgres"
$env:AIOPS_DATABASE_URL = "postgresql://aiops:aiops_password@localhost:15433/aiops"
$env:AIOPS_EVENT_BUS = "kafka"
$env:AIOPS_KAFKA_BOOTSTRAP = "localhost:29092"
$env:AIOPS_RAG = "qdrant"
$env:AIOPS_VECTOR_DB_URL = "http://localhost:16333"
```

容器内 API/Worker 自动使用 `postgres:5432`、`kafka:9092`；宿主机调试默认使用 `localhost:15433`、`localhost:29092`、`localhost:16333`，分别对应 PostgreSQL、Kafka、Qdrant。

## 9. 真实修复执行器

默认 `AIOPS_REPAIR_EXECUTOR=dry-run`，审批通过后只记录修复意图，不执行系统命令。需要真实执行时，必须显式切换为 `allowlist`，并提供 JSON 参数列表；只允许 `restart` 和 `rollback` 两类动作，命令不会经过 shell：

```powershell
$env:AIOPS_REPAIR_EXECUTOR = "allowlist"
$env:AIOPS_REPAIR_COMMANDS = '{"restart":["docker","restart","{service}"],"rollback":["kubectl","rollout","undo","deployment/{service}"]}'
$env:AIOPS_REPAIR_TIMEOUT = "30"
```

执行阶段状态依次为 `executing`、`resolved` 或 `execution_failed`。失败会记录错误并回写熔断器；相同任务不会重复执行。

## 10. Docker API/Worker

在项目根目录执行：

```powershell
docker compose -f .\02_Source\agent_tech_portfolio\docker-compose.production.yml up -d --build redis api worker
Invoke-RestMethod http://127.0.0.1:18024/health
docker compose -f .\02_Source\agent_tech_portfolio\docker-compose.production.yml ps
```

API 容器使用 `8000` 端口，默认映射到宿主机 `18024`（可用 `AIOPS_API_PORT` 修改），Worker 使用 Celery `solo` 池；SQLite 数据保存在命名卷 `aiops_app_data`。停止本项目容器但保留数据：

```powershell
docker compose -f .\02_Source\agent_tech_portfolio\docker-compose.production.yml stop api worker redis
```

## 11. 当前边界

- 默认是仅本机演示配置，API Key 认证可选启用；公网部署必须启用认证，并由密钥管理服务负责轮换和吊销。
- 当前是轻量 API Key 角色权限，没有接入企业 OAuth2/OIDC 单点登录或用户目录。
- 审批恢复已使用 SQLite 原子条件更新，能防止多进程重复审批；如果未来改用多数据库分片，才需要额外的分布式锁。
- 默认内存安全状态只适合单 API 实例；多实例部署必须显式设置 `AIOPS_SAFETY_BACKEND=redis`。
- 默认 dry-run 不执行真实变更；allowlist 执行器只适合明确隔离的演示或受控环境，生产环境仍应接入专用变更平台。
- `/health` 只是进程存活检查；`/ready` 检查 SQLite、当前启用的 Kafka 和 Neo4j。DeepSeek 真实请求仍需要单独业务监控，以避免探针产生费用。
- 本项目没有把参考材料中的生产指标、团队职责或上线结果写成用户经历。
